## 5. Целевой REST-контракт (состояние-на-04.10.2026 из заметки)

| Метод | Путь | Тело | Ответ (ключевое) |
|---|---|---|---|
| GET | `/` | — | манифест API + `notes` (текущий контракт поведения) |
| GET | `/health` | — | `{ok:true}` (НЕ гарантирует выдачу — см. §8) |
| GET | `/state` | — | `{busy{active,rid,path,since,last}, current, depth, nav, tabs}` (не блокируется) |
| POST | `/search` | `{query, page_size, category?, page?}` | `{total, pages, docs[], categories[], selected_category, requested_category, scope, truncated, parsed_count, expected_count, filter_applied, empty_reason, note}` |
| POST | `/page` | `{page}` | docs[] N-й страницы текущего поиска |
| POST | `/doc` | `{page, index}` | `{kind: document|collection|unavailable, title, content?, entries?, links?, message?}` |
| POST | `/sub` | `{index}` | текст пункта подборки |
| POST | `/open` | `{ref}` / `{title}` / `{uri}` | прямой доступ (ref из links[] — быстрее всего) |
| POST | `/back` | — | вверх по стеку навигации |
| POST | `/issues` | `{title,description?,endpoint?,severity,steps?,expected?,actual?,reporter}` | 202 `{ok,id,status:"new",...}`; `tags` НЕ слать (500) |
| GET | `/issues` | `?limit=200&status=new` | журнал заявок |
| GET | `/issues/<id>` | — | одна заявка |
| PATCH | `/issues/<id>` | `{status, note?}` | смена статуса + `resolution_note` |

### Поведенческие гарантии (regression-цели)
- `[ ]` `scope="single_section"` — поиск по ОДНОМУ разделу; без `category` детерминированно
  берётся крупнейший лист дерева, видно в `selected_category`.
- `[ ]` Несуществующая `category` → **HTTP 400** `unknown_category` + `categories` + `hint`.
- `[ ]` Спуск агрегата (`leaf=false`) — только в собственный дочерний лист; без подмены.
- `[ ]` Целостность: `truncated`, `parsed_count==expected_count`, `len(docs)==min(total,page_size)`.
- `[ ]` Пустая выдача различима: `empty_reason="no_matches"` vs `"list_not_rendered"`.
- `[ ]` Дефисная форма номера дела → честный `total=0` + `empty_reason=no_matches` + `note`.
- `[ ]` `gui_lock` таймаут → HTTP 504 `gui_busy` со снимком очереди; `/state` не блокируется.
- `[ ]` `/doc kind=collection` всегда с непустым `entries[]`; `title` без водяного знака.
- `[ ]` `/sub` над подборкой возвращает текст пункта, не коллекцию.

### Что теперь гарантировано в контракте API

- `total` берётся только из позиции читалки «Док. N / total»; если не читается —
  `total=null`, `pages=null`, `total_source="unavailable"`. Никаких «0 найдено» из ниоткуда.
- `empty_reason` различает «правда нет документов» (`no_matches`, подтверждённый
  `section_count=0`) и техническую неспособность прочитать GUI
  (`tree_not_read`, `list_not_rendered`, `section_not_selected`, `results_page_not_opened`).
  Второе всегда даёт `ok=false, retryable=true` и никогда не выглядит как пустая выдача.
- Список перечисляется с повтором (2 попытки: сброс модалок → «Все результаты» → выбор
  раздела), дерево разделов перечитывается до 3 раз до `unknown_category`.

- Анти-протечка прошлого списка: проверка заголовка страницы выдачи по запросу,
  `rows_identical`, `stale_suspect`, `dropped_rows`; кэш-хит восстанавливает сессию
  (`_hydrate_session`, `cached`, `_age`) и помечает `from_cache=true`.
- Адресация строк: `docs[].ref="pos:<abs>"`, в `/doc`, `/sub`, `/open` принимаются
  `index` (0-based, как в `docs[].index`), `row` (1-based) или `ref`; промах — 400 с

  если страница результатов не открылась.

  цифр/дат), при `no` — `ok=false` и прямой запрет использовать `content` как цитату.
