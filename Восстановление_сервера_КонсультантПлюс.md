# Восстановление сервера «КонсультантПлюс» — воркфлоу

> Составлен 02.11.2026 по итогам диагностики: сервер **недоступен**. Файл собирает все известные данные о том, как сервер работал и должен работать, и задаёт пошаговый порядок восстановления.
> Основные источники: `tools/README_КонсультантПлюс.md` (руководство, ред. 04.10.2026), `roleplay/ПРОТОКОЛ_КонсультантПлюс.md` (контракт сверки), `data/Общее/ИСТОРИЯ.md` (строки 01–04.10.2026), карточки памяти проекта.

## 1. Что представлял собой сервер (факты из истории)

- **Это не HTTP-сервер базы данных, а обёртка над интерфейсом**: GUI-автоматизация «КонсультантПлюс» (поиск + открытие документов в окне программы), упакованная в REST JSON. Под капотом — одиночный GUI-поток, поэтому обработка **строго последовательная**, сессия **одна** (новый `/search` затирает предыдущий и сбрасывает стек навигации).
- **Машинка-хост**: отдельный компьютер в домашней сети с адресом `192.168.1.105` (статический или по резервации роутера — проверить, см. шаг 3). На нём установлены: сама программа «КонсультантПлюс» с активной лицензией/индексом, скрипт автоматизации GUI и HTTP-обёртка на порту **8000**.
- **Похоже на FastAPI/uvicorn**: манифест отдаёт только `GET /`; `/openapi.json`, `/docs`, `/help` — 404 (документировано в руководстве).
- **Переменные окружения (известные)**: `CONSULTANT_GUI_TIMEOUT` — таймаут gui_lock, по умолчанию 120 с; флаг `--llm-fallback` — привлечение локальной модели (LM Studio) для классификации document/collection при сомнении.
- **Журналы на сервере**: `logs/issues.log` (приём заявок), `logs/missing_bases.log` (обращения к недокачанным базам — по нему базы докачиваются).
- **Эволюция API**: 01.10.2026 поднят с 3 эндпоинтами (`/health`, `/search`, `/doc`, `/page`); в тот же день обновлён до 8 (добавлены `/open`, `/sub`, `/back`, `/state`); к 04.10.2026 — 13 эндпоинтов (добавлен трекер заявок `/issues`). Манифест `GET /` полнее, чем примеры в `tools/consultant_plus.py` (в CLI нет команд `/page`-по-умолчанию-сессии и `/issues`).

### Поведенческие гарантии, которые были достигнуты 04.10.2026 (regression-цели при проверке)

1. `scope="single_section"` — поиск всегда по ОДНОМУ разделу; без `category` детерминированно берётся крупнейший лист дерева, видно в `selected_category`.
2. Несуществующее имя раздела → **HTTP 400** `unknown_category` со списком `categories` и `hint` (не молчаливый игнор).
3. Спуск агрегата (`leaf=false`) — только в его собственный дочерний лист; подмена чужим разделом устранена (`cc786b1033e2`).
4. Целостность выдачи: `truncated`, `parsed_count == expected_count`, `len(docs) == min(total, page_size)`; молчаливая обрезка исправлена (`8845aeef6a3c`).
5. Пустая выдача различима: `empty_reason="no_matches"` vs `"list_not_rendered"`; устойчиво пустой запрос не советует повторять (`e1cd42fb7152`).
6. Дефисная форма номера дела (`88-8986/2025`) → честный `total=0` + `empty_reason=no_matches` + `note` с объяснением (`c41315453682`); индексация дефисной формы НЕ обещана.
7. gui_lock 120 с → HTTP 504 `gui_busy` со снимком очереди; `/state` не блокируется (`2ff2fd1d70ef`).
8. `/doc`: `kind=collection` всегда с непустым `entries[]`; «мёртвых» пустых коллекций нет; `title` без водяного знака (`ef1566bc5e7e`, `172908c2bff7`).
9. `/sub` над подборкой возвращает текст пункта, а не коллекцию (`736ab61267ef`).
10. **Открытая заявка `2d0fe9de9645` (high, new)**: `/doc {page,index}` может держать GUI-очередь 15+ минут, отмены по rid нет. Пока не закрыта — правила безопасности из `data/TODO.md`: `/state` перед каждым GUI-вызовом, **не вызывать `/doc {page,index}`**, полный текст через `/open {ref}` / `/open {title}`.

### Тайминги эталонной работы

- Один запрос 17–55 с; `/page` — 3–15 с; `/doc` — 5–90 с; `/open?ref` — ~17,5 с (при 489 658 знаках).
- Рабочий размер: `page_size=20`; клиентский таймаут ≥ 150 с; `try/except` на каждом шаге; волна ≤ 3–5 запросов, чекпоинт-отчёт после каждого шага.

## 2. Текущая диагностика: что проверено 02.11.2026

| Проверка | Команда / артефакт | Результат |
|---|---|---|
| Health клиента | `tools\venv\Scripts\python.exe tools\consultant_plus.py health` → `temp\_restore_health.txt` | **TimeoutError WinError 10060** — соединения нет вообще (не HTTP-ошибка, сеть не отвечает) |
| ICMP | `ping 192.168.1.105` | 100 % потерь — хост недоступен |

| Подсеть рабочего места | `ipconfig` → `temp\_restore_arp.txt` | ноутбук в сети **`192.168.2.0/24`** (Wi-Fi, `192.168.2.55`, шлюз `192.168.2.1`); Ethernet «Среда передачи недоступна» |
| Обход текущей подсети | `temp\_restore_sweep.py` → `temp\_restore_sweep.txt` | в `192.168.2.0/24` порта 8000 не открыто ни на одном хосте — сервер туда не переезжал |

| Скрипты верификации | `temp/cp_verify_w1..w6.py`, `cp_fix_status.py`, `cp_fix2_check.py` | на месте — готовы к прогону после поднятия сервера |

**Главная находка:** сервер, скорее всего, **не сломан, а недоступен из-за смены сети**. 04.10.2026 всё работало на `192.168.1.105`; сейчас рабочее место подключено к другой подсети (`192.168.2.0/24`, Wi-Fi), а прежний Ethernet-канал «недоступен» (кабель не подключён). Хост `192.168.1.105` из этой сети не маршрутизируется и не отвечает.

**Вероятные причины (по убыванию вероятности):**

1. Ноутбук в другой сети (другой роутер/точка доступа/переезд) — сервер жив, но «не виден».
2. Серверная машина выключена / спит / выдернута из сети.
3. Сменился IP серверной машины (DHCP без резервации), при сохранной подсети.
4. На серверной машине погас сам сервис (GUI «КонсультантПлюс» закрыт, автоматизация/uvicorn не перезапущены, слетела лицензия/обновление программы).

## 3. Воркфлоу восстановления

### Шаг 1. Восстановить сетевую достижимость (проверяется за минуты)

1. Вернуть ноутбук в домашнюю сеть: подключить Ethernet-кабель (порт сейчас `Media disconnected`) или подключиться к Wi-Fi той сети, где был `192.168.1.105` (судя по истории — домашняя сеть `192.168.1.0/24`).
2. Перепроверить: `ping 192.168.1.105`. Отвечает — переходить к шагу 3.
3. Не отвечает, а сеть та же — искать машину сервера физически (питание, сон, кабель) и её актуальный IP: посмотреть в списке клиентов роутера (`192.168.1.1`) по имени машины, либо прогнать обход подсети скриптом `temp/_restore_sweep.py` (править список IP на `192.168.1.1..253`, он ищет порт 8000 и стучится в `/health`).

### Шаг 2. Поднять сервис на серверной машине (192.168.1.105)

> Расположение кода сервера и порядок его запуска **не документированы в этом репозитории** (сервер поднят владельцем 01.10.2026; скрипт автоматизации живёт на машине сервера). Пункты ниже — чек-лист по признакам из истории; уточнить у владельца/разработчика СПС фактический путь запуска.

1. Запустить «КонсультантПлюс» (GUI) до состояния рабочего окна поиска — автоматизация работает с интерфейсом, ей нужны открытая программа и активная лицензия/проиндексированная база.
2. Запустить обёртку-сервер (похоже на uvicorn/FastAPI) на порту 8000; если запускалась с `--llm-fallback` — при необходимости рядом держать запущенным LM Studio (классификация document/collection через локальную модель).
3. Убедиться, что `CONSULTANT_GUI_TIMEOUT=120` (иначе зависший GUI-поток снова станет бесконечным).
4. Проверить локально на машине: `curl http://127.0.0.1:8000/health` → `{"ok": true}`; затем с ноутбука — `http://192.168.1.105:8000/health`.
5. Если менялся IP машины — закрепить адрес в роутере (DHCP-резервация по MAC) или настроить статический: весь клиентский код и документы завязаны на `192.168.1.105`.
6. Посмотреть `logs/issues.log` на машине — нет ли неразобраных заявок (в т. ч. `2d0fe9de9645` про зависание `/doc` — она всё ещё `new`).

### Шаг 3. Проверить API по контракту (health ≠ работоспособность)

История знает три вида деградации, когда `/health` врал: (а) живые тексты норм ГК/НК/ГПК не выгружаются при `ok:true`; (б) `export_len=0` при живых `/health`/`/state`; (в) GUI-воркер висит на `/doc` 15+ минут. Поэтому:

1. `GET /health` → `{ok:true}` — базовый признак.
2. `GET /state` → `busy.active=false` (если `true` и `since` растёт — GUI-поток завис, перезапустить сервис).
3. Контрольный `/search` без `category` (запрос «ст. 247 ГК РФ порядок владения и пользования», `page_size=20`): проверить `selected_category` непустым, `truncated=false`, `parsed_count==expected_count`, `len(docs)==min(total,20)`.
4. Контроль 400: `/search` с заведомо несуществующим `category` → HTTP 400 `unknown_category` (не молчаливый игнор).
5. Контроль `empty_reason`: мусорный запрос → `no_matches` без совета повторять; дефисный номер дела (`88-8986/2025`) → `total=0` + `empty_reason=no_matches` + `note`.
6. Контроль `category="Судебная практика"` + `16-КГ23-26-К4` → `selected_category="Решения высших судов"`, `total≈10`, подмены чужим разделом нет.
7. Полный текст — только быстрым путём: `POST /open {ref}` из `links[]` или `POST /open {title}`; **не гонять `/doc {page,index}`** до закрытия `2d0fe9de9645`. Если `/state` показывает `busy.active=true path=/doc` — это известный висняк, не долбить, ждать/перезапускать сервис.
8. Промерить тайминги: запросы 17–55 с — норма; 162–554 с при объявленном `op_limit_seconds=150` — признак деградации из октября (тогда работать по локальному корпусу, новую волну не гонять).

Готовые скрипты для прогона: `temp/cp_verify_w1.py`…`w6.py` (именно ими 04.10.2026 подтверждали все фиксы — это готовый regression-тест), `temp/cp_fix_status.py` (состояние заявок через `GET /issues`). Отчёты они пишут сами в `temp/_cp_*.txt` (UTF-8, кириллица целая).

### Шаг 4. Если IP сервера изменился — синхронизировать клиента и адреса в файлах

- `tools/consultant_plus.py` — константа `BASE` (строка 37); у пакетных `tools/cp_*.py` адреса могут быть продублированы — прогнать grep по `192.168.1.105`.

- Файлы с зашитым адресом (обновить после подтверждения нового IP): `tools/README_КонсультантПлюс.md`, `roleplay/ПРОТОКОЛ_КонсультантПлюс.md`, `roleplay/README.md` (карточки ролей и субагентов берут адрес из них; в `.qoder/agents/*.md` литералов адреса нет), `data/Порядок пользования/*` (иск, речь, README), архивные копии тестов кругов 1–3 (исторические — **не трогать**, правится только боевой трек и инструкции).

## 6. Симптом → действие (шпаргалка)

| Симптом | Наиболее вероятно | Действие |
|---|---|---|
| WinError 10060 / ping молчит | не та сеть / машина выключена / сменился IP | шаги 1–2 настоящего файла |
| `/health` ok, `/search` висит мин+ | деградация выдачи (октябрьский паттерн) | `GET /state`; перезапуск сервиса на машине; не гонять волны, работать по `temp/cp/` |
| `/health` ok, `export_len=0` в `/doc` | сломан экспорт тела документа | обход: `POST /open` с точным заголовком акта; заявка в `/issues` |
| `/state busy.active=true`, `since` растёт | GUI-воркер завис (заявка `2d0fe9de9645`) | не долбить; дождаться/перезапустить сервис; не вызывать `/doc {page,index}` |
| 504 `gui_busy` | очередь GUI занята (штатно) | читать `busy.last`, продолжить позже |
| `selected_category` ≠ заказанный | слетел фикс `cc786b1033e2` | реестр «не проверено: сервер подменил раздел» + `POST /issues` |
| HTTP 400 `unknown_category` | имя раздела не из `categories` | взять точное имя из ответа; фильтровать по `title` |
